# Output files

Each generation writes the files below into one new directory. See [CLI](cli.md)
for path rules and failure behavior. Equal definitions, versions and generation
configuration produce identical paths and bytes, without machine paths or
timestamps.

Related manuals: [CDC timing constraints](timing-constraints.md).

## File set

| File | Content | Condition |
| --- | --- | --- |
| `nocloom_<name>.v` | Top module in Verilog-2001 | Always |
| `nocloom_<name>.map.json` | Definition, ports, topology, resources and contracts | Always |
| `nocloom_<name>.bundle.json` | Integration file lists and top module | Always |
| `nocloom_<name>.dependency.json` | Resource waits and exclusions | Always |
| `nocloom_clock_gate.v` | Gate model or bound-cell wrapper | The network uses gates |
| `nocloom_synchronizer.v` | Asynchronous-reset synchronizer model or wrapper | The network uses synchronizers |
| `nocloom_synchronizer_sync_reset.v` | Synchronous-reset synchronizer model or wrapper | Synchronizers use synchronous reset |
| `<cell_module>.v` | Behavioral model of a bound library cell | That bound cell is used |
| `nocloom_<name>.ipxact.xml` | IEEE 1685-2009 component | `--ipxact` |
| `nocloom_<name>.address_table.json` and `.csv` | Per-initiator address windows | `--address-table` |
| `nocloom_<name>.cdc.sdc` and `.cdc_preserve.txt` | Timing exceptions and preserve list | `--cdc-constraints` |

Only the bundle records the generator version. The other output files do not
change when only the NocLoom version changes. The exception is
[error logging](error-logging.md#configuration) without `revision`. Its register
holds the generator version, so the RTL, map and dependency file change with it.

Each RTL file starts with the line `// Generated by NocLoom`. Generated files
identify
[NocLoom Output Permission 1.0](../LICENSES/LicenseRef-NocLoom-Output-1.0.txt)
with `LicenseRef-NocLoom-Output-1.0`. This permission covers only the content
that NocLoom supplies in the output files, including generated models, metadata
and constraints. It permits use, modification and distribution without Apache
Section 4 notices, license copies or source disclosure.

The limited Apache patent grant, its termination rule, the warranty disclaimer
and the limitation of liability remain. User material and third party material
keep their own terms. The generator remains under
[Apache 2.0](../LICENSES/Apache-2.0.txt).

JSON uses a top-level `_license` object. Other formats use comments. CSV readers
must skip the initial lines that start with `#`. License paths identify files in
the NocLoom release package.

Cell behavioral models are for simulation only. For synthesis, use
`synthesis_sources` from the bundle and the bound technology library.

## Map

| Area | Content |
| --- | --- |
| `definition` | Normalized endpoint configuration, topology, connectivity and address mappings |
| `ports` | Top-level names, directions, widths and endpoint roles |
| `network` | Routes, clocks, storage, adapters and bindings |
| `definition.contract` | Observable protocol, capacity, ordering and arbitration rules |
| `definition.log_registers` and `definition.error_logs` | Logger banks, fields, filters and route values |

See the [field index](map-fields.md) for JSON paths. Read generated identifiers,
route labels and target IDs from each map.

## Bundle

The bundle lists the top module, optional outputs, synthesis sources, simulation
sources and library cell models separately. Its `version` field is the generator
version.

## Address table

JSON and CSV derive per-initiator routing windows from the map. See the
[columns](#address-table-format).

## Dependency graph

The dependency JSON lists resource waits, ranks and exclusions. Cycles appear in
the file and CLI output without failing generation.

The file does not describe external dependencies inside your endpoints. See the
[endpoint requirements](timeout-and-progress.md#shared-request-and-response-paths).

## IP-XACT

`IpxactOptions` accepts vendor, library and version. Vendor and library default
to `nocloom`. Empty version uses `1.0`.

IP-XACT remap states reject conflicting input values or a `false` selector other
than one comparison of a one-bit input (`NCL_MODE_CONDITION`).

## Metadata

Map and bundle use `format_version: 1` without recording the input schema
version. Automatic graphs are marked as one switch per direction. Connected
pairs sort by name.

Only the endpoint ports listed in the map are a public interface. Declaration
order does not change artifacts where that order has no defined meaning.
[Route class](network.md#endpoint-flows) declaration indexes, fixed priority
lists, user-bit lists, flag declaration order and log observation order keep
their stated meaning.

## Address table format

JSON records format, generator, module, global width and initiators in name
order. Each initiator lists its default target and reached windows in base
order. CSV has one row per reached routing window. It excludes disconnected
targets and unmapped intervals.

Contiguous pieces of one mapping join into one window. Aliases keep separate
rows and local bases. A narrower initiator clips each window to its address
limit.

| Column | Meaning |
| --- | --- |
| `initiator`, `target` | Endpoint names |
| `base`, `size` | Global byte interval, hexadecimal and padded to the address width |
| `local_base` | Local target address corresponding to the global base |
| `access` | Read/write intersection, or `none` for opposite one-direction endpoints |
| `exclusive` | Network, target or no exclusive support for an AXI4 or AXI3 initiator. Other initiators have none |
| `default_target` | True for the selected default target's windows |
| `when` | Selection condition, with `&` between selectors and `!` for false |
| `flow` | Target flow, when the network has target flows |
| `source_paths` | Reaching flows, space-separated in CSV or a list in JSON, when connectivity excludes flow pairs |

Selection conditions can share an address. Their windows follow one another at
that base. `add_address_table` adds JSON and CSV and updates only the bundle
list. Input must contain one map, one bundle and no address table
(`NCL_ADDRESS_TABLE_INPUT`).

## Dependency format

An edge points from a blocker to what it can block. `format_version` changes
when a field changes meaning.

| JSON field | Meaning |
| --- | --- |
| `rules` | Rule IDs, names and endpoint or hardware level |
| `nodes` | Kind, key, component, domain, resource binding and rank |
| `edges` | Source, destination, rule and group. A nonzero group marks alternatives |
| `excluded` | Omitted relations and their associated conditions |
| `environment` | External nodes and their required assumptions |
| `fingerprints` | FNV-1a 64 hashes of RTL and map definition |
| `model` | Numbered transport tables for at most 4096 endpoint pairs, otherwise null with an omission reason |
| `result` | Cycle status, cycles, rules and suggested changes |

Acyclic edges increase rank. Cycles indicate possible waits without proving
reachability. The model excludes checks for omitted waits, missing clock wakes
and incorrect burst counting, so acyclicity does not establish system progress.

## IP-XACT integration

Each initiator is a subordinate interface with a memory map and opaque bridges
to connected target manager interfaces. Targets have address spaces, one segment
per distinct local interval, ending at the highest local segment. Initiator
memory maps contain reached global windows in 8-bit address units.

APB, AHB and AXI4-Lite targets with multiple flows have one bus interface per
flow, named with that flow suffix. AXI targets use one interface with flow in
the ID. The model has an RTL view and every top-level port. Known periods give
clock drivers in picoseconds. Ports narrower than fixed AMBA logical widths map
to their low bits.

Endpoint clocks and resets map to protocol clock and active-low reset signals.

The component refers to Arm's public AMBA bus and matching RTL abstraction
definitions, which the integrator must obtain separately. Bus definitions use
`amba.com`: AXI4 and AXI4-Lite AMBA4, AXI3 and APB3 AMBA3, APB4 AMBA4, APB2
AMBA2 and AHB-Lite AMBA3.

| Protocol | Bus definition version |
| --- | --- |
| AXI4, AXI4-Lite, APB4 | `r0p0_0` |
| AXI3, APB3, AHB-Lite | `r2p0_0` |
| APB2 | `r2p0_4` |

Ports absent from an AMBA abstraction stay plain model ports. These include
target HSEL and the target `hready` output, two-bit HRESP, timeout status, test,
enable, ungate and address inputs. The AHB target `hreadyout` input maps to
logical HREADY on the master interface. Its `hready` output feeds slave HREADY
inputs as a plain model port. AHB initiator HSEL, HREADY and HREADYOUT map to
their subordinate abstraction signals. See
[AHB target ready connections](ahb.md#target-ready-connections).

The component has neither register descriptions
nor file sets. Use the bundle to select RTL source files.

`add_ipxact` requires artifacts generated from the same definition. It adds XML
and changes only the bundle list.
